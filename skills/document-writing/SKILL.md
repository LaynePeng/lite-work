# 文档写作技能

当用户要求撰写正式文档时，按以下流程执行：

## 步骤

1. **明确文体与要素**：文档类型（方案/通知/制度/说明书/报告）、读者对象、
   篇幅、语气；关键信息缺失时用 ask_user 一次性问清（提供选项）。

2. **先列大纲**：给出章节结构请用户确认；用户直接给全文要求时可跳过。

3. **撰写正文**：
   - 用规范书面语；条款用有序列表；并列内容用表格呈现；
   - 用户提供的既有内容（合同条款、数据、名称）原样保留；
   - 需要外部依据时用 webfetch 查证并注明来源。

4. **生成文件**：
   - Word 交付 → docx_create；
   - 定稿/不可编辑场景 → pdf_create；
   - 文件名含文档类型与主题，如 `项目实施方案_v1.docx`。
   - **迭代修改**：在已有文档上补充内容 → docx_append（path 指向
     .outputs/ 下的 docx，content 为要追加的 Markdown，可 page_break
     分页开新章）；推倒重写才重新 docx_create。

5. 回复：文件路径 + 内容摘要 + 需要用户补充确认的点。

## 注意

- 涉及法律/财务/合规的表述提醒用户由专业人士审核；
- 不确定的日期、金额、责任人等留空并标注"（待补充）"，不编造。
