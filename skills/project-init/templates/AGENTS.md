## 目录契约（硬性）

| 位置 | 用途 | Agent 权限 |
| --- | --- | --- |
| 项目根目录 | **交付物**：用户要的成品（docx/xlsx/pptx/pdf/图表…） | 交付物只写这里 |
| `素材/` | 输入：用户上传与外部资料 | **只读**（禁止修改/删除/重命名） |
| `素材/原始/` | 上传原件 | 只读 |
| `素材/参考/` | 参考资料、外部引用 | 只读 |
| `中间产物/` | 草稿、检索结果、渲染中间件（非交付） | 可写 |
| `归档/` | 旧版本（`YYYY-MM-DD_<原名>`） | **只增不删** |
| `.lite-work/` | 运行时数据（会话/计划） | 勿动 |

- 交付物**直接写项目根目录**（如 `方案_v1.docx`），Finder/IDE 打开即见——
  不套子目录、不藏隐藏目录、不写 `素材/`。

## 文档更新规则（硬性）

1. **一切修订都走版本演进**。用户不满意、补充信息、纠错、追加要求时：
   读取当前版本 → 合并修改 → 写 `<主题>_v(N+1).<ext>` 到根目录 →
   旧版本移入 `归档/YYYY-MM-DD_<原名>`。
2. **禁止新增补充文件**。不允许用新文件承载补充/追加内容，包括但不限于：
   `X_补充.md`、`X_v2_补充.docx`、`补充说明.txt`、`*_addendum*`、`*_supplement*`、`*_追加*`。
   **一个交付物在任何时刻只有一个当前版本**；补充内容必须合并进下一版。
3. 过程性内容（草稿、检索摘录、渲染中间件）写 `中间产物/`——它不是交付物，也不算「补充」。
4. 命名：日期一律 `YYYY-MM-DD`；交付物文件名含主题与版本（`<主题>_vN.<ext>`）。

❌ 反例：用户对 `方案_v1.docx` 补充两点意见 → 新建 `方案_补充说明.md`
✅ 正例：读取 `方案_v1.docx` → 合并意见 → 写 `方案_v2.docx` → `方案_v1.docx` 进归档

## 边界

- ✅ Always：交付物只写项目根目录；命名带版本；修订前先读当前版本再合并；
  旧版本及时归档。
- ⚠️ Ask first：修改本 AGENTS.md、删除任何文件、把中间产物提升为交付物。
- 🚫 Never：修改/删除 `素材/`；删除 `归档/` 内容；用补充文件代替版本更新；
  把交付物写进子目录或隐藏目录。
