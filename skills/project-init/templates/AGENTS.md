## 目录契约（硬性）

| 目录 | 用途 | Agent 权限 |
| --- | --- | --- |
| `素材/` | 输入：用户上传与外部资料 | **只读**（禁止修改/删除/重命名） |
| `素材/原始/` | 上传原件 | 只读 |
| `素材/参考/` | 参考资料、外部引用 | 只读 |
| `产出物/` | 全部交付产出 | **只写这里** |
| `产出物/<品类>/` | 按品类存放交付物（见下） | 可写 |
| `产出物/<品类>/中间产物/` | 草稿、检索结果、渲染中间件（非交付） | 可写 |
| `产出物/<品类>/归档/` | 旧版本（`YYYY-MM-DD_<原名>`） | **只增不删** |
| `.lite-work/` | 运行时数据（会话/计划） | 勿动 |

- 品类：报告 / 演示 / 表格数据 / 图表 / 专利 / 论文（可按需新增，新增后建对应 `INDEX.md`）
- 交付物**必须**写进 `产出物/<品类>/`，禁止写在项目根、隐藏目录或 `素材/`。

## 文档更新规则（硬性）

1. **一切修订都走版本演进**。用户不满意、补充信息、纠错、追加要求时：
   读取当前版本 → 合并修改 → 写 `<主题>_v(N+1).<ext>` →
   旧版本移入 `归档/YYYY-MM-DD_<原名>` → 更新本品类 `INDEX.md`。
2. **禁止新增补充文件**。不允许用新文件承载补充/追加内容，包括但不限于：
   `X_补充.md`、`X_v2_补充.docx`、`补充说明.txt`、`*_addendum*`、`*_supplement*`、`*_追加*`。
   **一个交付物在任何时刻只有一个当前版本**；补充内容必须合并进下一版。
3. 过程性内容（草稿、检索摘录、渲染中间件）写 `中间产物/`——它不是交付物，也不算「补充」。
4. 命名：日期一律 `YYYY-MM-DD`；交付物文件名含主题与版本（`<主题>_vN.<ext>`）。

❌ 反例：用户对 `方案_v1.docx` 补充两点意见 → 新建 `方案_补充说明.md`
✅ 正例：读取 `方案_v1.docx` → 合并意见 → 写 `方案_v2.docx` → `方案_v1.docx` 进归档 → 更新 INDEX

## 边界

- ✅ Always：交付物只写 `产出物/<品类>/`；命名带版本；每次产出/修订后同步 INDEX；
  修订前先读当前版本再合并。
- ⚠️ Ask first：新增品类、修改本 AGENTS.md、删除任何文件、把中间产物提升为交付物。
- 🚫 Never：修改/删除 `素材/`；删除 `归档/` 内容；用补充文件代替版本更新；
  把交付物写进隐藏目录。
