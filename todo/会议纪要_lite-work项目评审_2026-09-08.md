## 二、议题与讨论

对 lite-work 项目（手写内核的通用 AI Agent 桌面应用：Python 内核 + React UI + Electron 外壳）进行多视角评估，三位与会者依次发言并互相回应。

### 各方最终立场对比

| 议题 | 架构师 | 后端工程师 | 前端工程师 |
| --- | --- | --- | --- |
| **上帝对象** | server/app.py 1457 行、app.py 1197 行 | 同意，路由闭包内联无法单测，P0 修复 | 前端 App.tsx 1808 行同病相怜 |
| **事件/SSE 类型安全** | EVENT_MAP 全 dict 名不副实 | 同意，emit 无运行时校验 | SSE 路径大量 `as any` 侵蚀类型 |
| **连接健壮性** | CORS 全开 + 鉴权可选 | SSE 无断开清理、emit 吞异常 | 无重连策略、stall 检测未实现 |
| **测试盲区** | 测试对插件有隐式依赖 | LLM 真实 API 测试为零 | 前端几乎无组件测试 |

### 共识点（三方一致）

1. **三层都有巨型单文件**：`server/app.py`（1457 行）+ `app.py`（1197 行）+ `App.tsx`（1808 行）+ `styles.css`（5544 行），重构优先级最高；
2. **类型安全名不副实**：后端 EVENT_MAP 值全为 dict、前端 SSE 处理大量强制转换，均为"名义类型"；
3. **连接/错误处理薄弱**：SSE 无重连与断开清理、事件总线吞异常丢 traceback、前端仅单层 ErrorBoundary；
4. **值得称道的设计**：洋葱中间件 Pipeline（39 行）、安全四层纵深（堵复合命令绕过）、ContextManager 两阶段裁剪、多 Agent 三重限额 + 目录硬隔离、前端 80ms 节流流式渲染与纯 reducer 的 Agents 看板。

### 分歧点与裁决

| 分歧点 | 各方立场 | 裁决 |
| --- | --- | --- |
| pytest-asyncio 依赖性质 | Arch 称"隐式依赖"，BE 纠正为 pyproject 显式配置 + conftest 未显式导入 | BE 正确，属"可显式未显式"，成本极低应补上 |
| AgentApp 是否该拆 | BE 承认对 15K 行桌面应用有一定务实性 | 功能可先不拆，但**路由必须先拆**（无法单测是硬伤） |
| 重构优先级 | Arch 偏架构、BE 给了 P0-P3、FE 偏 UX | 安全与可测性优先，UX 平滑跟进 |

## 三、决议事项

以下为本次会议确认要执行的工作项，按优先级排列：

### P0（安全与可测性，低风险高收益）
1. **拆分 `server/app.py`**：路由拆分为多个 APIRouter（sessions / llm / skills / agents / office / security），解决 50+ 路由闭包内联无法单独测试的问题；
2. **CORS 白名单化 + 默认开启 Bearer 鉴权**：`allow_origins=["*"]` 改为白名单，token 为空时不再直接跳过鉴权。

### P1（类型安全与健壮性）
3. **事件 payload 改 TypedDict + 运行时校验**：`EVENT_MAP` 值从 `dict` 改为带结构的 TypedDict，`emit()` 加结构校验；
4. **`AgentLoop.run_task` 抽离三阶段**：268 行单方法拆为 LLM 调用 → 工具执行 → 状态更新，可独立测试；
5. **SSE 健壮性**：连接状态指示（绿/黄/红）+ 断开自动重连（指数退避）+ 30s stall 检测提示。

### P2（测试与 UX）
6. **补测试盲区**：LLM 适配器真实 API mock 测试、SSE 断开场景测试、前端组件测试；
7. **长对话虚拟滚动 + 分层 ErrorBoundary**：消息列表虚拟化（react-window / virtuoso），子组件崩溃按区域兜底不白屏。

### 暂缓项（本次会议决定不做）
- ❌ 引入 Redux / Zustand 状态管理库（单窗口应用收益有限，手写状态 + 抽 hooks 足够）；
- ❌ CSS Modules 全面改造（可用 CSS 变量分层渐进）。
