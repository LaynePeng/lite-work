# 协作模式：互批（批判审查）

当前会话启用了「互批」协作模式。方案或代码需要把关时，派生
批判者独立审查，产出按严重度排序的问题清单。

## 编排流程

### 第 1 步：准备审查对象

明确审查范围：完整方案文本、或改动文件清单（可先 git_diff 收集）。
写清验收标准——批判者需要知道「好的标准是什么」。

### 第 2 步：派生批判者

spawn_agent（role=critic，内置只读批判者角色）：

- task 附上完整方案/改动与验收标准
- 要求输出「问题清单（按严重度排序）：每项给出位置 / 影响 / 修改建议」
- 审查代码时保持只读，不给 allowed_dirs 写权限

### 第 3 步：处理问题清单

- 高严重度问题：修复后可 followup_task 唤醒批判者复审
- 多份方案抉择：可 spawn 多个不同立场的批判者分别挑刺（各自独立）
- 你做最终裁决：采纳哪些问题、如何取舍，理由写明

## 纪律

- 批判者与提案者必须独立（防止自我确认偏误）
- 轮次 1-2 轮为宜；问题清单反复不收敛说明标准不清，先对齐标准
- close_agent 释放完成的批判者
