# PPT 使用手册（模板 · 编辑器 · 交 AI 应用）

> 适用范围：lite-work v2（内置 `ppt-master` 技能 + `ppt_edit` 工具 + `PPT 编辑器`页签）。
> 本文所有操作与路径均按当前代码核对过，可直接照做。

## 0. 三十秒速查

| 你想做什么 | 走哪条路 | 入口 |
| --- | --- | --- |
| 从零快速出一份版式干净的稿子 | **从模板做 PPT** | 页签栏右侧「✨ 从模板做 PPT」／空对话页首屏按钮 |
| 已有 PPT 想换个设计，内容保留 | **套用模板重排** | 侧栏「文件」→ 右键 `.pptx` →「✨ 套用模板重排」 |
| 已有 PPT 只想改几处文字/数字 | **PPT 编辑器** | 侧栏「文件」→ 单击 `.pptx` |
| 说不清怎么改，让 AI 判断着改 | **标注 → 交 AI 应用** | 编辑器右侧「标注」页 + 顶部「交 AI 应用」 |
| 批量/脚本化改一堆文件 | **直接对话** | 对话里说，AI 调 `ppt_edit` |

以上入口共用同一份实现（`litework/tools/ppt_edit.py`），改完落盘结果一致，不会互相打架。

## 1. 从模板做 PPT

### 1.1 打开

- **页签栏右侧**：`✨ 从模板做 PPT`（一直可见，任何页面都能点到）
- 或者：新建一个空对话，首屏中央的「✨ 从模板做 PPT」按钮

> 早期版本这个入口只在**空对话首屏**出现，聊过一次之后就再也找不到——已修，现在常驻页签栏。

### 1.2 界面构成

三块，从左到右：**选设计 → 排页面 → 填内容**。

```
┌─ 左：设计 ─────────────┬─ 右：页面编排 ──────────────────┐
│ 版式套件（7 套）        │ 快速结构（一张封面 / 精简 / 完整）│
│  通用演示 16:9 · 20 页  │                                │
│  报告体 · 13 页         │ 第 1 页  封面                  │
│  杂志内页 · 10 页       │   主标题  [__________]         │
│  …                     │   副标题  [__________]         │
│                        │ 第 2 页  标题 + 内容           │
│ 品牌配色（21 个）       │   页标题  [__________]         │
│  ● McKinsey ● BCG …    │   正文内容[__________]         │
│                        │                                │
│ 设计风格（14 个）       │ 添加页面（点模板页名追加）      │
│  MBB Consulting …      │                                │
│                        │        [生成并打开编辑器]       │
└────────────────────────┴────────────────────────────────┘
```

### 1.3 三类资产不要混淆

| 资产 | 数量 | 作用 | 会改什么 |
| --- | --- | --- | --- |
| **版式套件**（layouts） | 7 | **真正能出稿的模板**，每页带 `{{TITLE}}` 之类占位符 | 决定页面结构与画布尺寸 |
| **品牌配色**（brands） | 21 | 只是一个主色 + 适用场景说明 | 只影响色板，不改结构 |
| **设计风格**（styles） | 14 | 给 AI 读的设计方法说明（Markdown） | 机械填充不用它；重排时作为上下文 |

所以**选品牌不会换版式**，它只把主色灌进配色；选风格主要影响 AI 重排时的写法。

### 1.4 可用版式套件一览

| 套件 `suite` | 名称 | 页数 | 画布 | 典型页面 |
| --- | --- | --- | --- | --- |
| `presentation_core` | 通用演示（16:9，20 页） | 20 | 1280×720 | 封面、章节、要点、双栏、对比、三卡片、KPI 看板、流程时间线、数据叙事、图表洞察、表格汇总 |
| `presentation_core_43` | 通用演示（4:3） | 16 | 4:3 | 同上（老投影仪/打印用） |
| `report_core` | 报告体 | 13 | 16:9 | 封面、章节、议程、KPI 行、2×2 矩阵、附录、结尾（自带页码/页脚占位符） |
| `editorial_bleed` | 杂志内页（出血大图） | 10 | 16:9 | 全幅大图、半幅出血、图注三联、四宫格、金句 |
| `moments_square` | 方图（社交媒体） | 8 | 1:1 | 封面、主张、双栏、三行、图片页 |
| `story_vertical` | 竖版故事（手机） | 9 | 9:16 | 封面、编号列表、步骤流、双块 |
| `xiaohongshu_post` | 小红书笔记 | 10 | 竖版 | 封面、卡片堆叠、引用、步骤流 |

最常用的是 `presentation_core`：日常汇报、复盘、方案都有对应页型。

**高频页面 slug**（填 `page` 字段时可以直接写 slug）：

| slug | 中文 | 占位符 |
| --- | --- | --- |
| `title_slide` | 封面 | `TITLE` `SUBTITLE` |
| `title_content` | 标题 + 内容 | `PAGE_TITLE` `CONTENT_AREA` |
| `section_header` | 章节分隔 | `CHAPTER_TITLE` `CHAPTER_DESC` |
| `two_content` | 双栏 | `PAGE_TITLE` `LEFT_CONTENT` `RIGHT_CONTENT` |
| `comparison` | 对比 | `PAGE_TITLE` `LEFT_TITLE` `LEFT_CONTENT` `RIGHT_TITLE` `RIGHT_CONTENT` |
| `three_card` | 三卡片 | `PAGE_TITLE` `CARD_1` `CARD_2` `CARD_3` |
| `kpi_dashboard` | KPI 看板 | `PAGE_TITLE` `KPI_1`…`KPI_4` `CONTENT_AREA` |
| `process_timeline` | 流程时间线 | `PAGE_TITLE` `STEP_1`…`STEP_4` `KEY_MESSAGE` |
| `hero_statement` | 观点金句 | `KEY_MESSAGE` `SUBTITLE` |
| `chart_insight` / `table_summary` | 图表/表格洞察页 | `PAGE_TITLE` `KEY_MESSAGE` `SOURCE` |

占位符留空不报错，但会在结果里提示「第 N 页未提供 XXX（按空值导出）」——照着补就行。

占位符值里写 `\n` 会变成**软换行**（导出后在 PowerPoint 里是真的换行）。正文类
占位符（`CONTENT_AREA` / `BODY_TEXT` / 各 `*_CONTENT`）请一个要点一行。

### 1.5 操作步骤（AI 生成，默认路径）

1. 左侧点选**版式套件**（切换套件会重置方案）；可选点**品牌配色**、**设计风格**；
2. 中间输入框写一句需求，例如「给管理层做 Q3 经营复盘：营收与毛利变化、三个增长点、两个风险、下季度三件事」；
   - 点「试试」里的示例可以直接套模板改；
   - 可选填**受众/场合**与**页数**（不填就交给 AI 决定，一般 8–12 页）；
3. 点底部「**✨ 规划方案**」——一次模型调用后出现逐页方案：左边页码列表、右边该页的版式下拉 + 各占位符文案；
4. 逐页微调：改文字、换版式（同名占位符的文案会保留）、↑↓ 调顺序、✕ 删页；
5. 满意后点「**生成并打开编辑器**」。

模型不可用或输出不合规时，会自动降级成「按版式排好的骨架页」（文案留空），
并在方案上方说明原因——直接在编辑器里补字即可，不用重新开始。

### 1.6 手动编排（需要精确控制时）

顶部切到「**手动编排**」：

1. 右侧点「快速结构」预设快速铺页面：
   - `只要封面` = 只有封面
   - `精简汇报` = 封面 + 2 页内容
   - `完整结构` = 封面 / 章节 / 内容 / KPI / 内容 / 金句
2. 逐页填占位符（正文类是多行框，其余是单行框）；
3. 需要更多页就点下方「+ 页面名」追加，用 ↑ ↓ ✕ 调整顺序或删除；
4. 点底部固定栏的「**生成并打开编辑器**」（与页面列表分离，页多也不会被滚走）。

生成过程通常几秒（首次要跑模板转换，大稿十几秒）。完成后**当前页签直接变成该 PPT 的编辑器**，不额外弹新页签。

产物位置：

- 生成的 pptx → 项目根目录（文件名默认取套件名，可自行改名）
- 编辑器工作区 → `中间产物/ppt-edit/<文件名>/`

## 2. 对已有 PPT 套用模板重排

适用于「内容留着，设计换掉」。

1. 侧栏切到「文件」页签；
2. 在 `.pptx` 文件上**右键** →「✨ 套用模板重排」；
3. 页面会先读源文件结构，逐页显示：页码、标题、段落摘要、类型标签（表格/图表/图片）；
4. **自动**触发一次规划（不需要再点按钮）：AI 按当前选中的套件把旧稿逐页映射到新版式、精简改写文字；
5. 在方案里逐页微调（改文案、换版式、调顺序、删页）；
6. 点底部「**生成并打开编辑器**」。

> **整个重排都在这个页签里跑完**，不会把你踢到对话页签。这一点是刻意的：
> 早期版本点「交给 AI 规划重排」会把消息丢进对话页签，模板页签留在原地什么
> 也不做——用户眼里那个 tab 就废了，做完还要自己找回来。现在读结构→规划→
> 生成→进编辑器是一条闭环，生成完成时**当前页签原地变成编辑器**。
>
> 需要让 Agent 做更复杂的重排（比如带表格/图表的精细重建）时，仍可以在
> 编辑器里用「标注 → 交 AI 应用」的通道，把意图打包给对话页签的 Agent。

## 3. PPT 编辑器（直接改已有文件）

### 3.1 打开

侧栏「文件」页签 → **单击** `.pptx`。走的是内置编辑器，不会用系统 PowerPoint 打开。

首次打开需要导入转换（建 roundtrip 工作区），等几秒。

### 3.2 三栏布局

| 区域 | 作用 | 操作 |
| --- | --- | --- |
| 左：幻灯片轨 | 看全貌、跳页 | 点缩略图；有标注的页显示「N 标注」，有未提交改动显示「N 待提交」 |
| 中：画布 | 看实际效果、选元素 | 点任意元素出蓝框；底部缩放控件（适应窗口 / 1:1 / ±） |
| 右：检查器 | 改属性 / 写标注 | 只在选中元素时出现，`Esc` 收起 |

键盘：`←` `→` 翻页，`Esc` 取消选中。

### 3.3 两种改法（关键区别）

#### ① 属性页 —— 确定性改动，直接写文件

选中元素 → 右侧「属性」页。**不经过 AI**，你填什么就是什么。

| 元素类型 | 能改什么 |
| --- | --- |
| 文本 | 内容（多行）、字号（pt）、颜色、左/中/右对齐、X/Y/宽/高 |
| 表格 | 点单元格直接改文字，失焦即保存 |
| 图表 | 改每个数据点数值，导出仍是原生图表 |
| 图片 | 换图（输入工作区相对路径 + 回车）、位置尺寸 |

**两级提交（务必注意）**：

- 文本/字号/颜色/对齐/位置：改完要点「**加入待提交**」，画布立即预览；再点**顶部**「提交改动 (N)」才真正写盘；
- 表格单元格 / 图表数值：失焦**立即写盘**（它们是 JSON 结构，无法用覆盖样式预览）。

「加入待提交」后若改主意，点顶部「放弃」即可丢弃草稿。**失败条目会留在草稿里**，不会静默丢失。

#### ② 标注页 —— 需要判断的改动，交给 AI

选中元素 → 右侧「标注」页 → 写一句话 → 保存标注。

写得好的标注：

```
✓ 这行太挤，精简成 3 个要点
✓ 标题换成更口语的说法
✓ 把这个表格拆成两张，按区域分
✓ 配图换成更商务的风格
✗ 改一下            ← 太模糊，AI 只能猜
```

标注**不会立刻生效**，它只是记下「你想怎么改」。要真正执行，点顶部「**交 AI 应用 (N)**」。

一次可以标很多处（跨页也行），计数器累加。

### 3.4 「交 AI 应用」到底做了什么

1. 读出全部待应用标注（页码 + 元素 id + 你的原话）；
2. 打包成一条消息发给 Agent，提示词要求：`outline` 读结构 → `edit` 逐条落实 → `export` 导出新 pptx → 逐条 `annotate`（需带 `slide` + `element_id`）清掉已应用的标注；
3. 自动**切到对话页签**，你能看到 Agent 逐条做了哪些改动。

已应用的标注之所以要**逐条**清（而不是一条命令清全部）：`ppt_edit` 的 `annotate`
要求 `slide`、`element_id`、`note` 三个参数同时给，`note="__clear__"` 只是表明
「这次是清除」。只传 `note` 会被直接拒绝——这条提示词已经按实际参数校验固定下来。

> **修过的一个坑**：早期版本 PPT 编辑器页签没有 `sessionId` 槽位，直接在这里发消息会把新建的会话绑到编辑器页签上——任务其实跑起来了，但界面不显示任何对话，用户看到的完全是「点了没反应」。现在发消息前会先落回对话页签（复用已有的空对话页签，没有才新建）。
>
> 如果仍然「点了没反应」，按顺序查：
> - 顶部有没有出现 toast「已把 N 条标注交给 AI」——没有就是**还没保存标注**，按钮会提示你去标；
> - 页签栏是否切到了 💬 对话页签；
> - 左下「日志」按钮里找 `💬 已切回对话页签执行` 与 `➤ 提交任务…`；
> - 对话页签里是否有红色错误条（多半是模型未配置 / 后端 401）。

### 3.4.1 两个 PPT 页签里「按钮点了没反应」的历史坑

这两个页签的主按钮都曾因为**样式缺失**而看起来不像按钮，用户以为点了没反应：

| 页签 | 按钮 | 曾经的症状 | 现状 |
| --- | --- | --- | --- |
| PPT 编辑器 | 交 AI 应用 | 无标注时 `disabled`，点了毫无反馈 | 始终可点；无标注时提示怎么标 |
| 模板页签（重排/新建） | 生成并打开编辑器 · ✨ 规划方案 | 无背景无边框的裸文字（101×19px）、还在滚动区末尾要滚到底 | 蓝色主按钮，固定在底部动作栏 |

根因是全局 `button { border:none; background:none }` 重置了外观，而 `.btn` 只在
`.ppt-editor` 作用域补过样式 —— 模板页签漏了。现已补 `.ppt-tpl .btn`，
并有 CSS 契约测试锁住（改回旧写法会立即测试失败）。

### 3.5 导出

顶部「导出」→ 生成 `<原文件名>_edited.pptx`，落在项目根目录。

**未改动的页字节级原样保留**，设计不会漂移；表格与图表仍是 PowerPoint 里能继续编辑的原生对象，不是贴图。

### 3.6 改动存在哪里

- 编辑工作区：`中间产物/ppt-edit/<文件名>/`
- **原 pptx 全程不动**，随便改；只有点「导出」才产出新文件。
- 重复打开同一文件会**沿用之前的编辑**（防手滑丢工作）。要从零开始需显式重新导入（`ppt_edit op="open"` 传 `reimport=true`）。

## 4. 直接对话改 PPT

不想点界面也完全可以，AI 调的是同一个 `ppt_edit` 工具。常用说法：

```
把 季度复盘.pptx 第 2 页的标题改成「2026 Q1 经营回顾」，然后导出
表格里华东的营收改成 4380
用 presentation_core 套件做一份 4 页的产品发布稿，品牌用 anthropic
```

`ppt_edit` 的全部操作：

| op | 作用 |
| --- | --- |
| `open` | 导入 pptx 建可编辑工作区（`reimport=true` 丢弃旧改动重来） |
| `outline` | 读页结构（元素 id / 类型 / 位置 / 文本），可带 `slide` 只看一页 |
| `slide_svg` | 取单页 SVG |
| `thumbs` | 全部页缩略图 |
| `edit` | 确定性改动：`text` `font_size` `fill` `align` `x/y/width/height` `table_cell` `chart_value` `image` |
| `annotate` | 写自然语言标注（`note="__clear__"` 清除） |
| `annotations` | 列出待应用标注 |
| `export` | 回写 pptx（未改页字节级 passthrough） |
| `templates` | 列出套件 / 品牌 / 风格 |
| `create_from_template` | 按模板填充生成 |
| `extract` | 读已有 pptx 的逐页语义结构（重排的第一步） |

判断该用哪条：

- **知道确切值** → 界面属性页（快、准、没有模型误差）
- **需要判断怎么改** → 标注（AI 帮你想）
- **批量 / 脚本化** → 对话

## 5. 边界与已知限制

| 做不到 | 替代方案 |
| --- | --- |
| 增删表格行列、增删图表系列 | 用「标注」让 AI 处理 |
| 整页重新排版 | 用「标注」或「套用模板重排」 |
| 旁白音频、转场动画 | 不支持 |
| `.ppt`（旧格式） | 先 `office_convert` 转 `.pptx` |
| 从零生成一份全新 PPT（不想管模板） | 用 `pptx_create` 工具直接生成 |

另外两点：

- **字号显示的是 pt 不是 px**：面板数值与 PowerPoint 里看到的一致（内部按 3:4 换算，不用管）。
- **只支持 `.pptx`**：`.ppt` 会明确报错让先转换。

### 5.0 能力速查（v2 新增）

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 长文本自动排版 | 自动 | 按占位符宽度折行 + 字号阶梯缩排；500 字长文案不再导出失败 |
| 原生表格 | `pages[].table` | `[[表头],[行]…]` → PowerPoint 可编辑表格 |
| 原生图表 | `pages[].chart` | `{categories, series}` → 可编辑图表（非贴图） |
| 增删页 | 编辑器「+ 复制本页 / + 新页 / 删本页」 | 结构变更后自动降级 flat 导出 |
| 换版式 | 编辑器页头下拉 | 文案按占位符顺序自动迁移 |
| 单页预览 | 规划结果页 | 编辑文案时实时渲染「这页长什么样」 |
| 单页重写 | 规划结果页「✨ 重写本页」 | 一句话让 AI 只改这页 |
| 演讲者备注 | 编辑器「备注」按钮 | 导出 pptx 时写入备注栏 |
| 导出 PDF | 编辑器「导出 PDF」 | 需本机 LibreOffice；失败不作废 pptx |
| 深色主题 | 模板页侧栏 ☀️/🌙 | 色板替换、布局同构 |

### 5.1 ppt-master 是内置技能，不是插件

PPT 的模板填充、套用重排、图形化编辑器**都依赖内置技能 `ppt-master`**
（`skills/ppt-master/`，含模板资产与 `pptx_to_svg.py` / `svg_to_pptx.py` 转换脚本）。
它是**随安装包分发**的，不在插件市场里——**不需要也不能单独安装**。

技能缺失时（安装包不完整、被误删、打包漏带），各入口的行为是明确报错，
而不是静默失败：

| 入口 | 缺失时的表现 |
| --- | --- |
| 「从模板做 PPT」/「套用模板重排」页签 | 显示「PPT 模板能力不可用：缺少内置技能 ppt-master」，含缺失原因、三项检查清单（技能目录 / 模板资产 / 转换脚本）、修复建议和「重新检测」按钮 |
| `POST /api/ppt/plan` | **409** + 修复建议（不是 422「未知套件」） |
| `POST /api/ppt/create`、`POST /api/ppt/open` | **409** + 修复建议 |
| `GET /api/ppt/templates` | 200，但 `layouts` 为空且带 `available.ready=false`——前端据此区分「模板库空」与「技能缺失」 |

自检：

```bash
# 开发态：仓库根应有该目录
ls skills/ppt-master/scripts/pptx_to_svg.py
ls skills/ppt-master/templates/layouts/
```

**不依赖该技能的能力**：由 AI 直接生成 PPT（`pptx_create` 工具、对话页签里说
「做一份 PPT」）走的是另一条路径，ppt-master 缺失也能用，只是没有版式模板套用。

### 5.2 AI 配图（生图大模型）

21 个版式里有 5 个带**图片位**（`title_picture` / `two_picture_caption` /
`picture_caption` / `editorial_split` / `screenshot_focus` 等）。勾选「用生图模型
配图」后，规划阶段会为这些页写画面描述，生成时调生图模型出图并填进图片位。

**不用额外配密钥**：凭据复用设置里已配好的聊天供应商——

| 已配置的供应商 | 使用的生图后端 |
| --- | --- |
| OpenAI | OpenAI（`gpt-image` 系列） |
| 通义千问（qwen） | 阿里通义万相 |
| 智谱（glm） | 智谱 GLM-Image |

都没配时开关是**禁用**的，并提示去设置里配；不会等到生成才报错。

其它后端（Gemini / FLUX / Ideogram / Stability / 火山 Seedream / 腾讯混元 /
fal / Replicate / SiliconFlow 等 12 个）不在上面这张表里：它们不是聊天供应商，
只能通过环境变量或 `~/.ppt-master/.env` 配置，界面不提供入口。

**提示词约束**：画面描述固定追加 `no text, no letters, no watermark`——
生图模型渲染文字几乎必错，PPT 的标题由版式自己排，图上不该有字。
规划结果里每条画面描述都能改（英文），改完再生成。

**失败不废稿**：单张配图失败只记 warning，其余页照常出稿；生成后提示会说明哪页失败。
产物落在 `素材/ppt-images/`。

#### 没有生图模型时：自动走开放图库

生图模型缺失**不等于配图不可用**。配图有两条通道，按能力自动选：

| 能力 | 通道 | 说明 |
| --- | --- | --- |
| 已配 OpenAI / 通义万相 / 智谱 | **生成** | 按内容画图，最贴合文案 |
| 都没配 | **图库** | 检索 Openverse / Wikimedia，**零密钥** |
| 两者都失败（网络断开等） | — | 单张记 warning，页面留空不阻塞出稿 |

图库通道的几个要点：

- 界面开关会**自动变成「自动配图」**并提示「未配置生图模型：将从开放图库检索配图」，
  不是灰掉；
- 检索**逐级放宽**：免署名（CC0/公版）高分辨率 → 允许署名高分辨率 → 允许署名降分辨率
  （有些图库只暴露 960px 预览图）；
- 用到需要署名的图（CC BY / CC BY-SA）时，生成结果会**列出哪页哪张图需要补出处**，
  不会默默用了侵权图；
- 生图失败（额度不足 / 限流 / 被安全策略拒）会**逐张降级**到图库，页面不会空着。

> 图库检索词会自动从英文画面描述里取前几个实词——图库是全文检索，长句命中率极低。

#### 需要代理的网络上：勾上「PPT 配图」scope

生图/图库脚本跑在子进程里，用的是 `requests`——它只能靠 `HTTP_PROXY` /
`HTTPS_PROXY` 环境变量走代理（不像 httpx 能传调用参数）。因此设置页的
**代理出网面**多了一项：

| scope | 影响 |
| --- | --- |
| `media` | PPT 配图（生图大模型 / 开放图库检索） |

- 不勾 = 配图直连（内网自建图床/无需代理时用这个）；
- 勾上后，代理地址与「直连列表（bypass）」都会注入子进程（`NO_PROXY`）；
- **应用里关掉代理时不继承 shell 的代理变量**——保证「关掉就是直连」，
  与 `llm`/`webfetch` 的 `trust_env=False` 行为一致。

```bash
# 命令行直连（调试用；走的是同一套脚本）
python3 skills/ppt-master/scripts/image_gen.py "aerial view of logistics hub" \
    --aspect_ratio 16:9 --image_size 1K -o 素材/ppt-images
python3 skills/ppt-master/scripts/image_gen.py --list-backends
```
