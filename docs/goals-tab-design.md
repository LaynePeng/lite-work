# 左侧栏「任务」Tab 设计（Goals 视图）—— personal agent 设计研究产出

> 状态：设计稿（未实施）。2026-10 调研 Muse（Meta，2026-09）/ dots（OpenAI，2026-09）
> 后的落地设计。前置变更：项目结构 v2（交付物平铺直给，产出物 Tab 已移除，
> 见 CHANGELOG 1.10.5）。

## 1. 布局哲学（产品定位）

```
┌────────────┬──────────────────────────┬────────────────┐
│ 左：操作面  │ 中：对话                  │ 右：执行信息     │
│ 用户发起与  │ 人机沟通的主通道           │ Agent 的过程     │
│ 管理一切    │                          │ 透明度           │
├────────────┼──────────────────────────┼────────────────┤
│ 项目 / 任务 │ 气泡 + 工具卡 + 审批卡     │ 上下文水位 /     │
│ 文件 / 终端 │ （Muse 的 chat bubbles）   │ 子Agent / 事件   │
└────────────┴──────────────────────────┴────────────────┘
```

原则：**左边是「我操作 Agent 的一切入口」，右边是「Agent 自己的仪表盘」**。
新 Tab 的取舍只问一个问题：这是用户主动操作的事，还是 Agent 的过程信息？
后者进右栏，不进左边。

## 2. Muse / dots 学到什么（对照结论）

| 对方设计 | 本质 | 结论 |
| --- | --- | --- |
| Goals Tab | 「Agent 在替我做什么」与对话解耦，目标/计划/进度成为一等公民 | ✅ 采纳为本设计的核心 |
| 透明度（activity log + 已批准权限） | 信任来自看得见 | ✅ 吸收进任务卡（最近活动）；权限面已在设置页 |
| Memory Files | 跨会话记忆，用户可读可编辑 | ⏳ 远期（需新子系统，见 §7） |
| 自定义规则（dots custom rules） | 用户可视化编辑 Agent 行为 | ⏳ 二期（「规则」Tab，见 §6） |
| Artifacts | 交付物直达 | ❌ 已由 v2 结构 + 文件树覆盖 |
| Ideas / 主动建议 | Agent 主动出击 | ❌ 远期（需常驻调度，超出按需模型） |
| 审批卡 Deny/Allow | 不可逆动作人类点头 | ✅ 已有（ApprovalGate） |
| 集成生态（dots 4000+ apps） | 能力面 | ❌ 管理面留设置页（MCP/插件/技能） |

**关键认知**：lite-work 的「会话」其实就是 Muse 的「Goal」——有目标（/goal 落
metadata）、有计划（TODO 看板）、有执行记录（事件流/W7 轨迹）、有组织行为
（subagent_records）。缺的不是数据，是**把会话从「聊天记录列表」升格为
「目标看板」的呈现层**。

## 3. 「任务」Tab 形态

### 3.1 任务卡（会话列表的增强视图，非替换）

```
┌─ 任务 ──────────────────────────── ＋ 新建任务 ──┐
│                                                   │
│ ┌───────────────────────────────────────────────┐ │
│ │ 📊 季度报告汇总                        62% 8/13│ │
│ │ ████████████░░░░░░░░                          │ │
│ │ ▶ 写正文第 3 章   ☐ 排版   ✔ 收集数据          │ │
│ │ 最近：docx_create 报告_v2.docx ✓  · 2 分钟前    │ │
│ │ 💰 $0.42 · 🤖 3 子Agent · [轨迹] [树] [续]      │ │
│ └───────────────────────────────────────────────┘ │
│ ┌───────────────────────────────────────────────┐ │
│ │ ✅ APP 竞品调研                          完成   │ │
│ │ 交付：竞品分析_v3.pdf（根目录）                 │ │
│ └───────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────┘
```

信息分区（从上到下）：

1. **标题 + 进度**：标题（会话 title）+ TODO 完成度（`8/13` + 百分比条）
   ——TODO 看板数据已按会话落盘（`litework/tools/todos.py` `_persist`）；
2. **当前步骤**：看板中 `in_progress` 项 + 相邻 pending 项（≤3 个）；
3. **最近活动**：事件流尾部一行的摘要（工具名 + 关键参数 + 成败）+ 相对时间
   ——Muse 头像下 snippet 的等价物；
4. **元信息行**：本会话累计成本（metrics 已有）· 活跃子 Agent 数
   （subagent_records）· 快捷入口（见 3.2）；
5. **完成态卡**收敛为单行：标题 + 交付物指针（根目录文件）。

### 3.2 卡片操作（点卡片 = 进入会话，其余收进 hover/右键）

| 操作 | 依赖 | 说明 |
| --- | --- | --- |
| 进入会话 | 现有 | 点卡片主体，同现在 |
| 轨迹 | `GET /api/trajectories/{session_id}`（W7 已有） | 抽屉/弹层看事件时间线 + findings |
| 子 Agent 树 | subagent_records（会话 metadata） | 派生关系图 |
| 续任务 | `/continue` 机制（App 端已有 AUTO_CONTINUE） | TODO 有未完成项时一键续推 |
| 派生 | 新会话继承 metadata | 从完成任务克隆目标 |
| 重命名/删除/置顶 | 现有 | 与会话列表一致 |

### 3.3 与现有「项目」Tab 的关系

- **项目 Tab 保留**，定位是**入口**：切换项目、最近打开、新建；
- 项目内二级视图（当前是会话历史列表）**替换为任务 Tab 的项目过滤视图**——
  即「任务 Tab + 选定项目」＝ 现在的会话列表位置，但呈现升格；
- 左栏 Tab 顺序：`项目 · 任务 · 文件 · 终端`；
- 任务 Tab 未选项目时显示跨项目全部任务（按最近活动排序），这是 Muse
  「Goals 是全局的」的等价物——**目标不属于某个聊天窗口，属于我**。

## 4. 数据与 API 差距

现有 `/api/sessions`（`routers/sessions.py list_sessions`）只返回
`title/message_count/updated_at/metadata`，需扩展：

```jsonc
// GET /api/sessions?workspace=... 响应新增（每会话）
{
  "todo_progress": { "total": 13, "done": 8, "current": "写正文第 3 章", "next": ["排版"] },
  "last_activity": { "summary": "docx_create 报告_v2.docx", "ok": true, "at": 1760000000 },
  "cost_usd": 0.42,
  "subagent_count": 3,
  "deliverables": ["报告_v2.docx"]   // 根目录交付物快照（可延后）
}
```

实现要点：

- **TODO 进度**：`TodoPlugin._load_disk(session_id)` 直读 JSONL，无需 Agent 参与；
- **最近活动**：会话事件流尾部（session_store 已有 messages；或 W7 轨迹尾部，
  轨迹开启时更结构化）；
- **成本**：`core/metrics.py`（tool_metrics 同源，按 session 聚合）；
- **性能**：列表页每卡聚合 3~4 个轻量读，需缓存（会话多时 O(n) 磁盘读要防）；
  建议后端一次聚合 + 前端 revision 刷新（与文件树同模式）；
- **向前兼容**：新增字段全部可选，旧前端无感。

## 5. 分期计划

| 期 | 内容 | 规模 |
| --- | --- | --- |
| P1 | 任务卡基础版：TODO 进度 + 最近活动 + 成本；项目内视图替换 | 后端 1 个聚合端点 + 前端卡片组件 |
| P2 | 轨迹抽屉（W7 透出）+ 子 Agent 树 + 续任务/派生 | 复用现有 API，主要是前端 |
| P3 | 跨项目全局视图（Goals 是全局的）+ 完成态交付物指针 | 视图过滤 + deliverables 快照 |

P1/P2 均不动 Agent 内核；P3 视使用反馈决定。

## 6. 二期候选：「规则」Tab（dots custom rules 思路）

定位：用户**操作** Agent 行为规则的入口（放左边，符合「操作面」）。

- 全局规则：编辑注入 system prompt 的稳定层（等价于全局 AGENTS.md）；
- 项目规则：可视化编辑项目根 `AGENTS.md`（模板字段化：目录契约/边界/常用命令）；
- 会话规则：会话 metadata 里的覆盖项（现有 /goal、collab 已是雏形）。

价值：AGENTS.md 目前要手改文件，非技术用户够不着；dots 把它做成了产品的一等
公民。规模小（编辑器 + 保存落盘），可与「任务」Tab 并行。

## 7. 远期：Memory（Muse Memory Files 思路）

Muse 的记忆跨会话且用户可读可编辑，这是 lite-work 当前模型（会话即孤岛 +
静态 AGENTS.md）的真实差距。但它是**新子系统**而非呈现层：

- 记忆写入时机（任务结束沉淀？用户显式「记住这个」？）；
- 记忆注入策略（全量注入会挤上下文，需检索式）；
- 与 W7 轨迹的关系（轨迹是原始数据，记忆是提炼结论——W10 reflection 的
  路线图里已有此规划，见 docs/ai-native-harness-roadmap.md）。

建议挂在路线图 W9/W10（metrics → reflection）之后，不与「任务」Tab 绑定。

## 8. 明确不做

- ~~产出物/Artifacts Tab~~：v2 结构已定，交付物在文件树根目录；
- 右栏并档到左边：执行信息是 Agent 的仪表盘，归右栏；
- 集成市场入左栏：管理面，归设置页；
