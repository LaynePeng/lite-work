# 隔离工作树（Isolation Worktree）工作流

> 目标：让 AI 在**独立分支 + 独立目录**里干活，主工作区始终干净；改动可审查、
> 可交给 AI 合并、也可一键丢弃。适用于需要「先隔离、后合并」的任务（重构、
> 批量改动、不信任的自动化、并行实验）。

## 一句话心智模型

**worktree = 给 AI 一个独立分支和目录干活；干完你审查，满意就合并（AI 也能帮你合并），不满意就丢弃——主工作区全程不动。**

## 全生命周期

```
① 开启
   /worktree on          （会话内开启；非 git 仓库会拒绝）
   项目列表 hover 🛡️      （新会话 + 自动开启）
   命令面板 /worktree ...  （on | off | list | clean）
        │
        ▼  从主工作区「当前分支」的 HEAD 创建：
          目录  <项目>/.lite-work/worktrees/<会话ID>/
          分支  worktree-<会话ID>
          依赖  node_modules / .venv / .env 自动 symlink（worktree 里也能跑测试）
        │
② 工作（正常对话）
   任务所有读写/命令都在 worktree 目录内执行；
   工具级隔离：写主工作区路径、cd 主工作区、GIT_DIR 重定向一律被拦截。
   主工作区可继续正常开发（也可以另开会话做别的事），互不影响。
        │
        ▼
③ 收割（任务结束 / 点合并时自动发生）
   worktree 的改动被**提交到 worktree-<会话> 分支**
   （Agent 自己提交过的也兼容，只补提交剩余部分）
   评审卡显示：变更文件 / 增删行 / 提交数
        │
        ▼
④ 决策（聊天区评审卡）
   ┌ 查看 diff        相对基点的完整 diff
   ├ 🤖 让 AI 合并     推荐：Agent 在主工作区 git merge --no-ff，
   │                  遇冲突逐个解决后完成合并提交
   ├ 直接合并          仅执行 git merge；冲突时留给用户（可再交给 AI / 放弃合并）
   └ ✗ 丢弃           删除 worktree + 分支，主工作区毫发无伤
        │
        ▼
⑤ 合并后
   主分支多一个 merge commit：`lite-work: 合并隔离工作树（<会话>）`
   自动清理 worktree 目录 + 分支，并关闭该会话的隔离模式
```

## 合并到哪个分支？

**主工作区当前所在的分支**（通常是 main / master / dev，不写死 main）。
评审卡会显示「合并到 <分支名>」；主分支若已前进（其他会话合并过），
会提示「主分支已前进，合并可能需要解决冲突——推荐让 AI 合并」。

## 多会话协作（同项目）

```
主工作区（分支 main）───────────────────────────────►
   ▲                    ▲                       ▲
   │ 合并(会话A)         │ 合并(会话B)            │
   │                    │                       │
 worktree-A ──► 分支 worktree-A（基于旧 HEAD）    │
 worktree-B ────────► 分支 worktree-B（基于更旧的 HEAD）
   ▲
   └ 会话 C 不开隔离，直接在主工作区改

规则：
- 每个隔离会话 = 一个独立分支，互不干扰；
- 合并是**串行**的：A 合并后主分支前进，B 的基点就落后了（评审卡出现「主分支已前进」提示），
  B 合并时可能需要解决冲突——交给「🤖 让 AI 合并」即可；
- 天然建议：一次只推进合并一个会话，合并完再处理下一个（冲突最少）。
```

## 与其他会话的「通知」机制

- 合并在**会话 A 内**执行，A 的界面实时看到合并阶段：
  `正在合并 → ⚠ 发现 N 个冲突（AI 正在解决）→ ✅ 已合并并清理`；
- 其他会话**不做实时推送**（它们可能根本没有任务在跑），而是在**切到该会话时刷新状态**：
  若主分支已前进，评审卡出现「主分支已前进」提示——这正是需要的信息；
- 因此不需要全局广播通道，避免了跨会话事件总线的复杂度。

## 清理与遗留

| 命令 | 作用 |
| --- | --- |
| `/worktree off` | 关闭模式；worktree **无改动**则自动清理（空壳不留） |
| `/worktree list` | 列出项目内所有 worktree（含各会话的） |
| `/worktree clean` | 清理所有**无改动**的 |
| `/worktree clean <名字>` | 只清指定那一个 |
| `/worktree clean all` | 全清（含有改动的，弹确认） |

> 有改动的 worktree 不会被 `off`/`clean` 静默删除——必须经评审卡「合并 / 丢弃」或
> `clean <名字>` / `clean all` 明确确认，避免误丢工作。

## 相关实现

- `litework/tools/worktree_manager.py` — worktree 生命周期（创建/收割提交/合并/丢弃/清理）
- `litework/server/tasks.py` — AI 合并任务（`merge_worktree` 参数 + 阶段事件 `worktree:merge`）
- `litework/core/agent_loop.py` — 工具级隔离检查（文件路径 / 命令 CWD / git 重定向）
- `web/src/components/ChatView.tsx` — 横幅 + 评审卡 + 合并阶段条
