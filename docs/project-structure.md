# 项目结构约定（根目录交付物 / 素材 / 版本归档）

lite-work 项目的推荐组织方式：**明确的 AGENTS.md + 交付物直接放项目根目录 +
素材/中间产物/归档 三个顶层目录**。配套工具是内置技能 `project-init`
（`skills/project-init/`），本文是它的约定说明。

> v2 结构（2026-10）：参考 Muse / dots 等 personal agent 的 Artifacts 思路
> ——**成品平铺直给**：交付物放最显眼的项目根目录，过程文件与版本历史
> 退到顶层目录。旧版 `产出物/<品类>/` 四层结构不再用于新建项目，存量项目
> 保留兼容（照常识别与读取，不迁移）。

## 目录总览

```
<项目>/
├── AGENTS.md                 # 项目最佳实践（Agent 每次任务自动读取并注入系统提示）
├── README.md                 # 人类入口（可选）
├── 方案_v1.docx              # 交付物：直接放项目根目录（文件名带版本号）
├── 季度报告_v2.pdf           # …品类信息用文件名表达，不用目录
├── 素材/                      # 输入：Agent 只读
│   ├── 原始/                  # 上传原件（上传文件默认落点）
│   └── 参考/                  # 参考资料、外部引用
├── 中间产物/                  # 草稿、检索结果、渲染中间件（非交付）
├── 归档/                      # 旧版本：YYYY-MM-DD_<原名>（只增不删）
└── .lite-work/                # 运行时数据（会话/计划），隐藏，不参与交付
```

## 规则

1. **命名**：日期一律 `YYYY-MM-DD`；交付物 `<主题>_vN.<ext>`；归档
   `归档/YYYY-MM-DD_<原名>`。
2. **版本演进（硬性）**：任何修订（用户不满意、补充信息、纠错）都是
   「读取当前版本 → 合并 → 写 `_v(N+1)` 到根目录 → 旧版进归档」。
   **禁止用新增文件做补充**（`X_补充.md`、`*_addendum*` 等）——一个交付物
   任何时刻只有一个当前版本。
3. **权限边界**：`素材/` 只读；交付物只写项目根目录；过程文件写
   `中间产物/`；`归档/` 只增不删。
4. **不建交付子目录**：图表/报告/论文等品类信息用文件名表达；目录层级
   只保留语义明确的三个（素材/中间产物/归档）。

## 工具（内置技能 project-init）

| 命令（相对技能目录） | 作用 |
| --- | --- |
| `python scripts/scaffold.py <项目根>` | 初始化结构（幂等，不覆盖已有文件；`AGENTS.md` 缺失时从模板生成） |
| `python scripts/new_artifact.py --name 主题 --ext docx [--project-root .]` | 分配下一版本文件名（版本号只增不减，目标为项目根目录） |
| `python scripts/archive_artifact.py --path x_v1.docx` | 旧版移入 `归档/YYYY-MM-DD_<原名>` |
| `python scripts/lint_artifacts.py [--project-root .]` | 检查补充文件违例（非零退出） |

## 新建项目自动初始化

桌面端「新建项目」入口在创建目录时即自动完成结构初始化（`素材/`、
`中间产物/`、`归档/`、`AGENTS.md`——由后端
`litework/tools/project_scaffold.py` 执行，打包态可用）；「新建代码」入口
**不**初始化结构、不生成 `AGENTS.md`，保持代码仓库干净。存量项目用上表的
`scaffold.py` 补建即可（幂等）。

## 项目类型（代码 / 项目）

项目类型与 git 解耦，按目录内容启发式判定（`classify_project_kind`）：
根目录有代码标记文件（`pyproject.toml` / `package.json` 等）→ 代码；
有 `素材/` / `中间产物/` / `归档/`（或旧结构的 `产出物/`）→ 项目；文档文件
（docx/pdf/pptx/xlsx）多于代码文件 → 项目；仅 `.git` 的空仓库 → 代码兜底。
最近项目列表可手动标记（行内 ⇄ 按钮），标记后锁定、不再被启发式覆盖。

## 与现有机制的衔接

- `AGENTS.md` 会被 `SystemPromptBuilder` 自动注入系统提示（项目指令），
  无需额外配置。
- office 工具（v1.6.0 起）交付物默认直接写项目根目录，上传素材落
  `素材/`（`UPLOADS_DIR_NAME`），中间产物（文档内嵌图表、渲染预览）自动落
  `中间产物/`，与本约定天然一致。
- 侧边栏「文件」页签可浏览/预览/下载全部交付物（根目录平铺，打开即见）。

## 设计参考

- Muse（Meta, 2026）/ dots（OpenAI, 2026）等 personal agent 的 Artifacts
  设计：成品是一等公民、平铺直给；过程文件退到幕后。
- AGENTS.md 开放标准（agents.md）：「agent 的 README」，保持精简、指针式。
- 旧版结构（v1，`产出物/<品类>/` + INDEX.md 体系）见 git 历史与本文件
  的 v1 版本；存量项目继续按原路径工作。
