# 第 13 课：知识篇综合复盘——从机制到架构的完整图谱

## 本课定位

前 12 课分三模块覆盖了三大主题：**ReAct 与循环（第 1-5 课）**、**代码理解与安全操作（第 6-9 课）**、**核心架构与多 Agent（第 10-12 课）**。本课作为知识篇收尾，不做技术新内容，而是把前三模块的知识点**按"模型层→能力层→编排层→界面层"四层架构重新组织**，帮你看清每个知识点在整个体系中的位置，并建立与实战篇 `lite-code` 项目模块的对应关系。

## 二、各层知识点精要

### 模型层（第 1-5 课）

**核心问题**：Agent 如何与 LLM 高效、可靠、低成本地交互？

| 知识点 | 关键结论 | 实战落地 |
|---|---|---|
| 流式 Tool Calling 解析 | 按 `index` 逐片拼接 `arguments`，流结束前不能 `json.loads` | `litecode/llm/openai_compat.py` |
| JSON 自愈 | 解析失败不 crash，回填错误信息让 LLM 自愈 | `litecode/core/json_repair.py` |
| 死循环检测 | 连续 N 次相同参数调用同一工具 → 强行中断 | `litecode/core/state_tracker.py` |
| 输出截断 | 行+字节双上限，超限落盘，上下文只放句柄 | `litecode/core/truncator.py` |
| Token 预算 | 90% × 模型窗口 = 有效上限，max(预算下限, 上限) 为裁剪阈值 | `litecode/core/context_manager.py` |
| 策略 B 两阶段裁剪 | 阶段1：压缩老轮次工具细节；阶段2：按轮删除（保留最新 K 轮） | 同上 |
| 静态 System Prompt | 任务内构建一次，逐字节不变，保持缓存前缀稳定 | `litecode/core/system_prompt.py` |
| Prompt 缓存 | 断点标注 + 稳定前缀；辅助调用复用主对话前缀 | 第 4 课全文 |
| 带外存储 | 大结果存磁盘，上下文只放句柄 + 路径 | `litecode/core/truncator.py` |

### 能力层（第 6-9 课）

**核心问题**：Agent 如何"看得懂"代码库、"安全地"改代码、"按需扩展"能力？

| 知识点 | 关键结论 | 实战落地 |
|---|---|---|
| 代码检索 | 索引（倒排/符号表）vs 全文扫描的取舍；Ripgrep 效率比纯 Python 快 10-100 倍 | `litecode/tools/codebase.py` |
| AST 分析 | Tree-sitter 增量解析 + 容错；骨架压缩省 60-80% Token | `litecode/tools/ast_tools.py` |
| 沙箱隔离 | 进程隔离、超时、环境变量擦除、高危命令过滤 | `litecode/security/guard.py` |
| 精确编辑 | Search-Replace 模糊退避 + Unified Diff 锚点偏移；失败回执触发 LLM 自愈 | `litecode/tools/editor.py` |
| Skills 系统 | 索引常驻 + 按需加载；指令注入优先级 | `litecode/tools/skills.py` |
| 权限治理 | 三级语义（allow/deny/ask）；deny 完整隐藏链 | `litecode/security/guard.py` |
| MCP 协议 | JSON-RPC 生命周期；外部工具默认审批 | `litecode/mcp/` |

### 编排层（第 2 课 + 第 10-11 课）

**核心问题**：Agent 如何"持续运转"、"多线协作"？

| 知识点 | 关键结论 | 实战落地 |
|---|---|---|
| AgentLoop | 异步 FSM：Send → Parse → Execute → Append → Repeat | `litecode/core/agent_loop.py` |
| 空响应自愈 | 连续 3 次空响应 → 终止；注入 user 消息"摇醒"模型 | 同上 |
| 工具并行化 | auto 模式：写类串行 + 只读并行；结果按原序回填 | 同上 |
| 待发送队列 | 任务运行中消息进入前端队列，任务完成后自动发送 | 前端 `PendingQueue` + `litecode/server/tasks.py` |
| 子 Agent 编排 | 独立 Kernel + 独立消息链；工具集按角色裁剪 | `litecode/orchestration/sub_agent.py` |
| 审批透传 | 共享 ApprovalGate vs 独立门；事件总线转发 | `litecode/security/approval.py` |

### 界面层（第 8 课 + 第 11 课）

**核心问题**：用户如何"看到"Agent 在做什么、如何"干预"？

| 知识点 | 关键结论 | 实战落地 |
|---|---|---|
| 审批卡 | asyncio.Future 挂起 → SSE 推送 → POST /api/approve 解挂 | `litecode/security/approval.py` |
| 提问条 | 非阻塞 inline 设计，固定在输入区上方 | `litecode/tools/ask.py` + 前端 `QuestionBar` |
| TODO 看板 | todo_write 全量覆盖 + todo:updated 事件推送 | `litecode/tools/todos.py` |
| 上下文面板 | 缓存命中率、窗口占用、压缩统计、预估成本 | `litecode/core/agent_loop.py` → SSE → UI |

## 四、为实战篇预热

从第 14 课开始，我们将进入手写 `lite-code` 的实战环节。下面是知识篇各课与实战篇的对应关系：

| 知识篇 | 实战篇落地 |
|---|---|
| L1 流式解析 + L2 循环/容错 + L3 上下文 + L4 缓存 + L5 Token | **L14 Core 内核 + L15 LLM 适配器 + L16 AgentLoop** |
| L6 代码理解 + L7 安全操作 + L8 Skills + L9 MCP | **L15 核心工具集** |
| L10 插件架构 | **L14 Core 内核（Kernel/Pipeline 实现）** |
| L11 多 Agent 协作 | **L18 安全沙箱（审批透传）+ L19 ask_user（提问条）** |
| L12 Agent 类型 | **L15 build_registry + L21 Web UI（Agent 切换）** |
| L8 权限治理（Skills 管理） | **L22 会话管理（设置弹窗）** |

实战篇不是简单重复知识篇的代码，而是：
1. 把知识篇的"最小示意代码"扩展为**生产级实现**（异常处理、边界检查、配置化）；
2. 把知识篇的"独立模块"**集成**到完整的 AgentLoop 中；
3. 为知识篇的"设计权衡"提供**真实的数据验证**（缓存命中率、压缩效率、并行加速比）。
